# AstrBot Discord GPT-Live

让 AstrBot 进入 Discord 语音频道，听大家说话并用语音回答。文字群聊里原有的人格、上下文和 Agent 可以继续用于语音对话，不用再单独维护一套机器人设定。

> 当前为早期版本。已在 Windows / Python 3.12 / AstrBot 4.22.1 环境完成实际语音测试，iPad 用户已确认能听到回答。多人接话、打断体验、跨文字与语音的记忆召回，以及长时间网络稳定性仍需进一步验证。

## 功能

- **持续语音对话**：接收频道成员音频，将多个真人的声音混合后送给 Live 模型，并持续播放模型回复。
- **复用 AstrBot 模型配置**：在插件里选择已有模型，直接读取模型名、接口地址、API Key 和自定义请求头；支持实现兼容 Live 协议的第三方服务。
- **沿用原群聊人格与上下文**：以发起加入命令的文字频道为绑定会话，语音需要查询旧事实时交给原群聊 Agent 处理。
- **文字与语音双向同步**：文字消息作为语音上下文，语音转录保存回原会话；支持已跟踪文字消息的编辑和删除同步。
- **可选文字触发语音**：默认只同步文字上下文，不主动朗读文字聊天；开启后允许模型回应相关文字消息。
- **同频道单机器人**：已有其他机器人或本机其他机器人正在加入时，拒绝第二个机器人入会并显示占用者名称。
- **退出与恢复**：所有真人离开约五秒后自动退出；未完成的历史写入保存在插件数据目录，供后续恢复。

## 安装要求

- AstrBot **4.22.1 或更新版本**，已配置 Discord 机器人。
- Python **3.10+**；当前实测环境为 Python 3.12，其他系统和架构请先验证语音依赖。
- Git、Opus，以及可以传输 Discord 语音的 **UDP 网络**。
- 支持 **Live 双向语音协议**的模型和 API 访问权限，例如 `gpt-live-1`。

普通聊天模型、仅支持 TTS 的模型，以及只实现其他实时语音协议的接口，不能直接用于本插件。第三方服务需要兼容 `/live/sessions` WebSocket、PCM 音频和客户端委派事件。模型名称可使用服务商配置的别名。

### 安装插件

在 AstrBot 插件管理中使用仓库地址安装：

```text
https://github.com/xiaozhejiya/astrbot_plugin_discord_gpt_live
```

也可以将本仓库放入 AstrBot 数据目录的 `plugins/astrbot_plugin_discord_gpt_live`，使用 **AstrBot 实际运行的 Python 环境**安装依赖：

```bash
python -m pip install -r requirements.txt
```

安装后重启 AstrBot 后台。插件管理器若已安装依赖，无需重复执行上述命令。

### Discord 语音依赖

当前固定使用包含 DAVE 收音修复的 [Pycord 提交](https://github.com/Pycord-Development/pycord/commit/10a5e8cf13bd8db21f95baf62cf866056d1e1091)，并固定 `davey==0.1.7`。davey 0.2.0 改变了密钥转换接口，不能单独升级该依赖。安装会影响同一 Python 环境中的 Pycord；替换依赖后需要重启后台，单独热重载插件不够。

HTTP 代理能连上 Discord 文字服务，不代表语音可用。使用代理时，UDP 必须能够通过完整代理链；遇到“没有路径”或入会超时，优先检查 UDP 和出口域名解析。

## 配置

1. 在 AstrBot 的模型配置中添加可用的 Live 模型，配置对应来源、接口地址和密钥。
2. 打开本插件配置，在“语音模型”中选择这条模型配置。
3. 选择服务支持的音色，按需要填写语音表达补充。
4. 确认发起命令的文字频道使用共享群聊会话，而非按成员隔离的会话。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `voice_provider_id` | 未选择 | AstrBot 原生模型选择器。读取所选模型及其来源配置，模型级设置优先。 |
| `voice` | `marin` | 音色名称，必须受所选服务支持。 |
| `voice_style_extra` | 空 | 补充语速、回答长短、倾听和插话风格；人格仍继承原群聊。 |
| `respond_to_text_in_voice` | `false` | 是否允许文字频道消息触发语音回应。两种状态都会同步上下文。 |

插件将 API 基础地址中的 `https` / `http` 转为 `wss` / `ws`，保留路径前缀并追加 `/live/sessions`。例如基础地址 `https://api.openai.com/v1` 对应 `wss://api.openai.com/v1/live/sessions`。代码不限定官方域名，也不会把其他来源的密钥自动发送到官方地址。

语音模型与原群聊的推理模型分别选择：前者负责持续听说，后者负责委派推理和记忆查询。修改模型、音色、来源配置或表达补充后，退出并重新加入语音频道生效。

旧版的 `openai_source_id` 和 `voice_model` 已替换为 `voice_provider_id`。升级时请先把原语音模型添加到 AstrBot 模型配置中，再在插件里选中它。

## 使用

先进入 Discord 普通语音频道，再在希望共享上下文的文字频道中发送命令：

```text
@你的机器人 /live_join
```

收到“已加入语音频道”后即可说话。机器人出现在成员列表中，只代表已开始入会，不代表语音链路已经完成初始化。

| 命令 | 权限 | 用途 |
| --- | --- | --- |
| `live_join` | AstrBot 管理员 | 加入发起者所在语音频道，并绑定当前文字频道。 |
| `live_status` | 普通成员 | 查看连接状态、同步积压和最近错误。 |
| `live_leave` | AstrBot 管理员 | 退出频道并保存待提交的会话内容。 |

命令前缀沿用 AstrBot 设置。机器人需要查看频道、连接和说话权限；目前不支持舞台频道。同一机器人在一个服务器中只能维护一个语音会话。

### 多个机器人

同一频道已有机器人时，包括音乐机器人，新的 `live_join` 会被拒绝。同一 AstrBot 内的多个机器人共用入会锁，连接中的会话也会占用频道；不同语音频道可独立使用。

这是入会检查，不会踢走后来加入的外部机器人。独立部署之间没有共享锁，同时入会仍可能受到 Discord 成员缓存延迟影响。收音层会过滤机器人音轨，但扬声器声音若被真人麦克风重新收进去，仍可能形成回声。

## 上下文、记忆与数据

文字和音频收发分别运行，历史与记忆约每两秒尝试后台提交；语音委派继续使用原群聊 Agent。原有人格或会话发生变化时，插件会重建 Live 上下文。

原始音频用于内存收发，不由本插件保存为录音文件。音频会发送到所选语音模型服务；绑定文字频道的上下文也会用于语音会话。语音转录写入 AstrBot 会话历史，未提交片段与恢复信息写入插件数据目录。长期记忆是否可用取决于原有记忆插件和模型配置。

启动上下文限制为最近最多 128 条、合计约 6,000 UTF-8 字节，较早内容通过原群聊 Agent 查询。多人混音目前不能可靠地逐人识别转录身份，语音委派仅开放已识别的群聊记忆查询工具。

## 已知限制与排查

| 现象 | 检查方向 |
| --- | --- |
| 入会超时、Discord 显示“没有路径” | UDP 是否通过完整代理链，出口域名是否被错误解析为本地 Fake-IP。 |
| 机器人已出现但没有加入成功提示 | 等待连接结果，使用 `live_status` 查看状态；尚不能认定初始化完成。 |
| 加入成功但听不到回答 | 检查客户端静音与音量、DAVE 依赖版本、模型权限及后台收音错误。系统加入提示音不能证明机器人音频已送达。 |
| 普通文字被语音回应 | 检查文字触发开关。此开关依赖模型指令，不是对所有输出的硬性拦截。 |
| 记忆查询较慢 | 原群聊 Agent 查询、会话锁等待和模型网络均会增加延迟。 |

本版本已通过真实 Live 启动及上下文同步测试、加密机器人双向音频测试、真人 iPad 可听回复测试，以及开发环境与桌面版框架下的自动化测试。多人自然对话、打断、语义记忆召回和真实网络下的 30 分钟稳定运行仍待验收，不承诺固定响应延迟。

持续连接可能按时长计费，原群聊 Agent 和记忆查询也可能产生额外调用费用；不用时请执行 `live_leave`。

## 开发与测试

目录保持按职责划分：`main.py` 处理命令与会话生命周期，`audio_bridge.py` 处理音频，`voice_session.py` 处理 Live 协议，`astrbot_bridge.py` 复用 AstrBot 模型与 Agent，`context_sync.py` 维护历史同步和恢复。

测试需要可导入的 AstrBot 环境。使用独立测试数据目录，不要把 `ASTRBOT_ROOT` 指向正在使用的机器人数据。安装开发依赖后执行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
python -m ruff check .
python -m ruff format --check .
```

仓库的 `scripts/` 提供可选真实服务探测，运行时会连接服务或进入指定频道：

```bash
python scripts/probe_live.py --config PATH_TO_CONFIG --provider-id ASTRBOT_MODEL_ID
python scripts/probe_voice.py --config PATH_TO_CONFIG --guild GUILD_ID --channel VOICE_CHANNEL_ID
python scripts/probe_memory.py --memory-root PATH_TO_LIVINGMEMORY_PLUGIN
```

`probe_voice.py` 专门使用两个测试机器人验证加密音频，因此绕过正式插件的单机器人准入规则。只在允许测试的服务器运行。提交问题时请附版本、复现步骤和脱敏日志，不要附 API Key、Bot Token 或完整配置文件。
